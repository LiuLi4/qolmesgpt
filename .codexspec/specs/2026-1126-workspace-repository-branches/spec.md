# 功能规格：Workspace 仓库画布与可追溯调查版本

Status: Ready for design。权威：[requirements.md](requirements.md)。开发位于 dev。

## 用户流程

点击 workspaces → 菜单右侧展开列表（顶部新建）→ 选择 Workspace → 右侧详情 → 仓库画布添加 Group 仓库节点 → 点击节点在右侧选 Group、多仓库和逐仓分支 → 保存 → 调查按各分支最新提交固定读取，结论展示完整 SHA 和读取状态。

## 功能与验收

- REQ-001（Sources: NEED-001, CON-003）：现有连接内选择有权限的跨 Group 仓库。服务端重新验证 Group、仓库、分支访问；越权、错误连接、重复仓库拒绝，原配置保留。
- REQ-002（Sources: NEED-002, NEED-007）：同一 Workspace 每仓一个调查分支，支持修改；分支不存在或未选择不得保存，不静默回退默认分支。
- REQ-003（Sources: NEED-003）：调查开始按已保存配置获取各分支最新提交，固定本次读取 SHA；同次调查不混入分支后续变化。每仓记录仓库标识、分支、完整 SHA（成功时）、读取时间、状态；结果与模型输入同源。重新调查重新解析。
- REQ-004（Sources: CON-001）：部分仓库失败继续可用仓库，失败仓库无伪造 SHA，显示原因与“证据不完整”。
- REQ-005（Sources: CON-002, OUT-001）：未证明与事故部署版本一致时显示“当前按所选分支分析”；不得声称还原事故版本，不按事故时间自动切换提交。
- REQ-006（Sources: NEED-004）：菜单精确使用 workspaces；点击展开侧栏列表，顶部新建，列表包含既有 Workspace（含未就绪状态）。
- REQ-007（Sources: NEED-005）：选中后右侧详情按 Workspace 隔离；刷新保留选中上下文，空列表引导新建，切换不触发日志消费或模型调用。
- REQ-008（Sources: NEED-006, DEC-001）：画布可添加多个 Group 仓库节点；每节点一个 Group，显示名称与仓库数量。保存后重载可见。
- REQ-009（Sources: NEED-007, DEC-001）：点击节点在画布右侧编辑 Group、多个仓库和各调查分支；提供保存反馈、失败反馈和取消；脏表单不被轮询覆盖。
- REQ-010（Sources: OUT-002, CON-003）：跨 Group 读取不扩展修复/MR/审批能力，原修复链路边界继续生效。
- NFR-001（Sources: CON-003）：凭据不进入浏览器响应、模型、日志或 Git 文件；Git 调用参数化、限定连接来源、禁止路径越界和 token 重定向泄漏。
- NFR-002（Sources: NEED-003, CON-001）：调查代码快照隔离于可变 checkout 与修复目录；取证有界并披露失败/省略；版本元数据由服务端生成而非模型编造。

## 边界与兼容

既有 Group 自动纳入与 SLS/调查卡片保留；旧数据以现有默认分支初始化调查配置。本期添加的跨 Group 仓库只参与调查。旧结果不伪造补填 SHA。自动读取开关保持原值。画布为仓库配置，不实现可执行流程连线、任意脚本或新审批工作流。
