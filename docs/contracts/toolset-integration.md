# Toolset 集成规范

## 用途

约束新的观测数据源如何进入 HolmesGPT，确保模型拿到可追踪、有限量且能自我修正的证据。

## 从 base 推导出的设计后果

项目通过 Python Toolset 统一外部观测系统入口，因此新增数据源应沿用 Toolset 注册、配置校验、Prerequisite 健康检查和结构化结果这条路径，而不是在 CLI 或 HTTP 层复制 API 调用。

## 架构不变量

- 外部 API 调用应集中在对应 Toolset 或其适配层，核心调查流程不直接依赖供应商 SDK。
- 查询必须在服务端限制时间范围、结果数量和过滤条件；禁止无界返回日志或集合数据。
- Toolset 返回值应包含查询参数、范围、来源和可操作的完整错误信息。
- 只读能力和写操作必须分开；写操作需要显式审批入口。
- 凭据只能从运行环境、Secret 或配置注入，不能进入源码、测试 fixture、日志或结果正文。

## 品味不变量

- 工具名、参数名和错误信息应让模型能判断下一步修复动作。
- 供应商字段应在边界处归一化，内部结果保持稳定形状。
- 测试优先验证行为和失败路径；外部 HTTP/SDK 调用使用 mock，不依赖真实账号。

## 本地自由

适配层可以选择供应商 SDK 或 HTTP，只要依赖方向、结果形状、限流边界和错误语义保持不变。局部字段映射可按数据源特点实现。

## 校验方式

使用对应 Toolset 单元测试、Ruff、类型检查、文档 fence 测试和 `poetry check --lock`。错误测试应检查查询范围、过滤条件和上游错误是否保留。

## 反馈闭环

线上错误、审查意见和重复出现的配置误用应先反馈到 Toolset 错误信息或测试；如果形成稳定边界，再更新本规范。

## 不覆盖

不规定具体模型、提示词内容、GitLab 工作流和部署平台的 Secret 实现；这些由对应 spec 和部署环境单独定义。
